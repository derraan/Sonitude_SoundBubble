One-page record of everything established on 2026-11-04 (training, realtime runtime, testbench, mic hardware, EP35 behaviour on the real array). Each section links to the detailed write-up and data.

## 1. Executive summary

1. **Training collapse root cause found and fixed.** `max_samples` took the *first N* label-sorted dataset folders, so lean splits fed 100% empty-target syn clips. The v2 run with the fix is **passing its distance-sweep gates** (dry 0.5–1.5 m ≈ −25 dBFS, 2–3 m ≈ −95 dBFS).
2. **The realtime path is clean.** Buzz sources (ring DC-hold, hard trims, limiter pitch-pumping, cold-start underruns, -O0 build) are fixed; live sessions run with **0 underruns**. Offline C++ output equals the Python runtime exactly.
3. **Mic hardware:** dev ch2 and ch5 are ~12.6/12.9 dB low (wideband, permanent); dev ch4 **toggles** with rig handling. The cause is acoustic/transducer-side (seat mount/port or module), **not** firmware, digital scaling or boot state. It's compensated by wideband-only mic gains (testbench defaults).
4. **EP35 on the real array is not usable as-is.**
   - Its output depends strongly on **recurrent-state history**: the same input gives 37–73 dB depending on preceding audio.
   - **Quiet periods lock it closed.** Live, an in-bubble talker is deleted (69–78 dB) at every pose, even 0.5 m straight ahead.
   - When open, it is **lopsided** (mirror azimuths up to 37 dB apart), **rejects sources below the array**, and leaves a **bright residue** (highs pass, lows cut).
5. **Priority next step is the model:** state-robust training (quiet gaps → in-bubble speech, stateful/long sequences, below-array positives). Then evaluate v2 on the bench recordings with offline fresh-state replay before any live use.

## 3. Realtime runtime (`edge/cpp`, `soundbubble-rt`)

| Problem | Fix |
|---|---|
| Underrun held the last sample (DC step at block rate = buzz) | 2 ms decay to zero, fade-in on resume |
| Ring trims and overflow dropped audio hard | Crossfaded splices |
| Silent fills (missing hops, padding, catch-up) spliced hard | Fades at every audio↔fill edge |
| Limiter: instant attack + 25 ms linear release re-clamped every pitch period | 15 ms hold + exponential release (ceiling still hard) |
| Model residue: 125 Hz hop-rate comb when suppressing | Wet residual expander (−58 dBFS, pure-wet DAC path only; taps stay pre-gate; `--wet-gate-dbfs off`) |
| Cold-start ORT runs starved the ring | 12 warm-up inferences before streams open |
| `build-local` was unoptimized (-O0) | Release build |
| **Tap overwrite:** a later flush overwrote a take's WAVs; flush/append data race | Flush closes the segment (disarm + swap under lock); never clobber (`*.partN.wav`) |
| Per-mic hardware offsets | `--mic-gains` (linear) / `--mic-gains-db`, by device channel, raw tap untrimmed |

Verification: 39 unit tests pass; offline C++ = Python runtime (correlation 1.000); live sessions 0 underruns.

## 4. Testbench (`tools/tech_testbench`, `tools/measure`)

- **Default model** EP35; bench gains: input +15 dB, model level −19 dBFS.
- **Mic gains:** six faders plus number boxes (linear), "Normalize to model", "Unity". **Defaults use the wideband-only rule:** ×1.514 (dev 0, 1, 3, 4), ×6.457 (dev 2), ×6.683 (dev 5).
- **Validity marks** (`pass` / `check` / `invalid`) via `mark_trial_validity`. Polar aggregation uses only valid takes per position. **Bug fixed:** polar cuts now hold the other angle (azimuth at el = 0, elevation at az = 0).
- **Speech campaign:** a folder stimulus generates a **random LibriSpeech utterance loop per take** (levelled, ~15 s), saved as `stimulus_used.wav` plus `stimulus_speech.json`. The Algorithm-tab campaign drives Setup, and there's a safety net so a speech campaign never plays the ESS.
- **Live takes record the running pipeline's actual settings**, with a `settings_mismatch` block and a log warning when Setup differs. **Setup edits need a pipeline restart.** Five mislabelled "25 dB" takes were corrected.
- **Known issues:**
  - `tools/measure/parity.py` is broken (DLL path, `dummy_realtime` import).
  - From Git Bash, `soundbubble-rt` needs `C:/Strawberry/c/bin` first on `PATH` (otherwise `0xC0000139`).
  - **Device indices change after a USB replug** (37→31, 41→35): re-select devices.
  - The Python runtime has no `--mic-gains`.

## 5. Mic array hardware

- **State:**
  - dev 2 −12.6 dB and dev 5 −12.9 dB: wideband (flat ≤ 2 dB, 250 Hz–8 kHz), repeatable to 0.05 dB over 10 runs including 5 USB power cycles.
  - dev 4 toggles low/normal with rig handling (normal since 05:37).
- **Root-cause evidence:**
  - The silence noise floor is −11 dB at LF but only −5 dB at HF, so the loss sits before the mic's own noise.
  - Deployed firmware cal is unity.
  - Offsets aren't an exact 12.04 dB; waveforms are clean and coherent.
  - The state doesn't change across power cycles.
- **Ranked hypotheses:** (1) seat mount/port, plus a contact issue on dev 4; (2) module sensitivity; (3) supply/ground. *Disfavoured:* firmware/I2S.
- **Decisive test:** swap the dev 2 and dev 3 modules.
- **Procedure:**
  - Before each session, stop the pipeline and run `python debug/mic_state_check.py`.
  - If dev 4 reads low, set its fader to about ×6.1.
- **Calibration rule:** correct only **wideband** offsets (≥ 6 dB, flat ≤ 3 dB); never flatten frequency-dependent (acoustic) differences.

Details: `docs/mic_low_state_investigation_20261104.md`, `docs/mic_level_anomalies_20261104.md`; data in `measure/mic_state_20261104/`.

## 6. EP35 behaviour on the real array

| Test | Key result |
|---|---|
| **Azimuth ESS sweep** (1 m, 13 takes, valid) | Lopsided: 30° 58.5 dB vs 330° 21.6 dB; the array itself is symmetric (±90° delays mirror). Not affected by the dev 4 issue (gains matched) |
| **Recurrent state** | Same 0° sweep: 37–73 dB depending on history (fresh 59.9; 167 s history 38.8); identical 90° takes 14 dB apart; live residue floor −48 dBFS vs −85 fresh |
| **Elevation ESS** (5 takes, `check`) | Live had dev 4 13 dB hot. Offline with **wideband-only correction**: −60/−30/+30/+60 improve 12–46 dB and keep is flat −12…−28 dB (100 Hz–8 kHz). Per-pose full normalization (superseded) failed at +60° because it erased natural ILD |
| **Speech, 0°** (15 takes) | Bimodal: closed (74–78 dB) or open-then-closing (−14…−34 dB, then −16…−29 dB within a take); switches between takes at identical input; open output is bright; +25 dB input worse |
| **Speech × elevation × distance** (11 takes) | Live: closed at every pose (69–77 dB), even 0.5 m at 0°, despite a restart 26 s earlier. Offline fresh: opens at 0°/above (0.5 m 0° 32 dB; 1 m +30° 40 dB), closed below (−60° 78 dB) |
| **Speech at 1.5 m** (3 takes, az/el 0°) | Closed live (66–69 dB) and from a fresh state (70–72 dB), including a take 5 s after a restart. Fresh-state distance curve at 0°: 0.5 m 32, 1.0 m 54, 1.5 m 70 dB, so the real-array bubble edge is ≈ 0.5–1 m, not 1.5 m. No out-of-bubble (2–3 m) recordings exist yet |

**Conclusion:** EP35's live behaviour is governed by internal state. Quiet periods drive it into a closed state that speech doesn't release. It also rejects below-array sources and passes a high-frequency-heavy residue. For a continuously running device this is a functional failure.

Details: `docs/polar_sweep_1m_ep35_20261104.md`, `docs/speech_algorithm_tests_ep35_20261104.md`, `docs/speech_elevation_tests_ep35_20261104.md`.

## 7. Recommendations (priority order)

1. **Model:**
   - Train for state robustness: long or stateful sequences, quiet gaps followed by in-bubble speech (learn to reopen), state carried across clips.
   - Add below-array in-bubble positives.
   - Revisit the SNRLP negative/positive balance for real data.
2. **Record a distance ladder at az 0°/el 0°** (0.5, 0.75, 1.0, 1.25, 1.5, 2.0, 3.0 m, ≥ 3 takes each). Far-talker rejection (2–3 m) is untested on the real array. Raw takes are model-independent and reusable for any future model via offline replay. Az/el at the 1.5 m edge is lower priority with EP35 (already closed at 0°).
3. **Evaluate v2 on the bench:** offline fresh-state replay of the existing raw takes (`debug/speech_offline_replay.py`, `debug/polar_offline/replay.py`) against EP35, then live takes right after a restart.
4. **Hardware:** module swap test (dev 2 ↔ dev 3); inspect seat ports/gaskets (dev 2, 4, 5); press-test dev 4.
5. **Runtime mitigation (interim):** state refresh via two staggered model instances with a crossfade, or a reset on voice-activity onset.
6. **Measurement protocol:**
   - Mic state check before each session.
   - Restart the pipeline after any Setup change.
   - ≥ 3 takes per pose with interleaved 0° references.
   - Prefer offline fresh-state replay for model comparisons.
   - Speech, not ESS, for algorithm tests.
